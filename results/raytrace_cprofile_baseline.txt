Totals
------

=> 1936.0 ms per render under cProfile instrumentation

Note on absolute numbers: cProfile's per-call instrumentation inflates
runtime roughly 2.5x versus the uninstrumented 787.7 ms per render. The
ABSOLUTE times below are therefore not comparable to the pyperf baseline;
the RELATIVE ranking and the call counts are what matter, and call counts
are exact.

Findings
--------

1. Loop-invariant object construction in the shadow-ray test (biggest win)

   Scene._lightIsVisible builds Ray(p, l - p) inside the loop over
   scene objects, but that expression depends only on l and p, which do
   not change across iterations. With 8 objects in the scene the same
   Ray is constructed up to 8 times per call for no reason.

   Ray.__init__ normalizes its direction vector, so each redundant
   construction costs a Point.__sub__, a Vector.normalized (which is a
   magnitude -> math.sqrt plus a scale that allocates another Vector).

   Evidence: the visibleLights/_lightIsVisible subtree accounts for
   4.557 s of 9.680 s, i.e. ~47% of total runtime. Ray.__init__ is
   entered 490,860 times with 1.936 s cumulative.

   Hoisting the construction above the loop is semantics-preserving:
   the loop body neither mutates the Ray nor depends on iteration
   order for its value.

2. Runtime type assertions that compute nothing

   Vector.mustBeVector is called 2,602,695 times and its entire body is
   "return self". Point.isPoint is called 1,389,325 times to return a
   constant False. Together that is ~4.0 million function calls whose
   only purpose is defensive type checking in code whose types are
   already statically known by construction.

   These are invoked from the hottest paths: Vector.dot calls
   other.mustBeVector() on every one of its 2,549,355 invocations, and
   Vector.__sub__ / Point.__sub__ do the same.

3. Object allocation churn

   Vector.__init__ runs 2,264,715 times. Vector, Point and Ray are all
   plain classes without __slots__, so every instance carries a full
   __dict__. Adding __slots__ reduces per-instance memory and speeds up
   attribute access, which matters given that dot alone performs six
   attribute reads per call.

4. Redundant work inside normalized()

   Vector.normalized (549,435 calls) calls magnitude() then scale(),
   allocating an intermediate and paying an extra Python-level call.
   Computing the reciprocal once and constructing the result Vector
   directly removes one call and one allocation per invocation.

Planned optimizations, in priority order
----------------------------------------
  1. Hoist the loop-invariant Ray out of _lightIsVisible
  2. Remove mustBeVector / mustBePoint / isPoint / isVector from hot paths
  3. Add __slots__ to Vector, Point, Ray and Sphere
  4. Inline the reciprocal in normalized(), dropping the scale() call
  5. Reduce attribute lookups in Sphere.intersectionTime

Each is applied and measured as an independent change so that its
individual contribution to the >=7% target is attributable.
