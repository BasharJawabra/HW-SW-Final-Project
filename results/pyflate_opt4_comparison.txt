Pyflate Optimization 4: Hoist Length Checks Out of the RLE Loop
===============================================================

Date   : 2026-09-21
Commit : f80ce06
File   : bm_pyflate_opt/run_benchmark.py
Target : the final run-length expansion in decode_huffman_block


The change
----------

Before:

    nt = nearly_there = bwt_reverse(b"".join(buffer), pointer)
    i = 0
    while i < len(nearly_there):
        if i < len(nearly_there) - 4 and \
           nt[i] == nt[i + 1] == nt[i + 2] == nt[i + 3]:
            out.append(nearly_there[i:i + 1] *
                       (ord(nearly_there[i + 4:i + 5]) + 4))
            i += 5
        else:
            out.append(nearly_there[i:i + 1])
            i += 1

After:

    nt = bwt_reverse(b"".join(buffer), pointer)
    i = 0
    end = len(nt)
    limit = end - 4
    while i < end:
        if i < limit and nt[i] == nt[i + 1] == nt[i + 2] == nt[i + 3]:
            out.append(nt[i:i + 1] * (nt[i + 4] + 4))
            i += 5
        else:
            out.append(nt[i:i + 1])
            i += 1


Rationale
---------

Three independent inefficiencies, all in the hottest remaining loop
(decode_huffman_block held the largest self time in the profile at
0.488 s):

  1. len(nearly_there) was recomputed on every iteration, and a second
     time inside the condition. nt is an immutable bytes object whose
     length cannot change during the loop, so both are loop-invariant.
     cProfile counted 674,570 len calls overall.

  2. ord(nearly_there[i + 4:i + 5]) allocated a one-byte slice and
     called ord on it, where indexing a bytes object already yields the
     integer directly. Verified equivalent for all 256 byte values:

         all(ord(b[i:i+1]) == b[i] for i in range(256))  ->  True

     This removed 76,108 ord calls plus the same number of slice
     allocations.

  3. The redundant alias "nt = nearly_there = ..." bound two names to
     the same object, and the loop used them interchangeably for no
     reason. nearly_there is unused after the loop, so the alias was
     dropped.

----------------------

allocations removed alongside the ord calls, which do not appear as a
separate line in the profile.
